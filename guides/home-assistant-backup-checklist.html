Five checks before you trust a Home Assistant backup

"Backup successful" means a file was written. It does not mean the file will restore, contains everything, or still works with your current version.

1. Age

How old is the newest good backup? A perfect backup from three months ago is still a three-month-old configuration. Set a threshold you are comfortable with — one day for an active system, seven days for a stable one — and alert when you cross it.

2. Size

Compare each backup against a rolling median. A sudden drop to 40% of normal size usually means an add-on or a config folder was skipped. A backup that is too small is worse than no backup, because you trust it.

3. Coverage

Confirm the archive actually contains what you need: configuration, add-ons, folders and the entity/device registries. Home Assistant can finish a backup while silently omitting a component.

4. Contents

Read the archive and verify its members against what the manifest claims. For encrypted backups, do not trust the metadata protected flag — check the archive itself. Path traversal entries must be rejected during extraction.

Answerable question: "If I wiped this machine right now, could I restore from the newest backup?" If you cannot answer yes with evidence, you do not have a backup — you have a file.

5. Restore drill

Extract the archive to a throwaway directory and check what is inside. Never run a drill against the live system. A drill is the only check that proves the archive is readable end to end.

Make it a habit
